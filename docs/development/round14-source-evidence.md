# 第十四轮：固定来源快照与主题证据关系

日期：2026-09-20。继续修改正式知识中心；新增迁移 `016_knowledge_evidence.sql`，未迁移或重启活动环境。

## 本轮用户流程

工作人员打开知识地图并选择主题，在“主题证据链”中浏览来源快照，查看来源版本、观察时间、生成方式、文件路径/行号和内容指纹。选择依据后填写背景、支持或反驳关系及说明，可明确标记已经人工核对该关联。保存后显示关联人员和说明，刷新仍可恢复；移除关联保留原始快照和文件依据。

主题可以在尚无文档时关联证据，也可以关联多个来源的证据。文档归类不会自动确认其引用支持主题，人工确认关联不等于已经验证生产行为。来源停用后，获准员工仍可查看历史依据；客户不能读取这些内部表或接口。

## 快照与证据模型

| 对象 | 本轮实现 |
| --- | --- |
| SourceSnapshot | `knowledge.source_snapshots`，记录一次完成构建的固定输入版本、原始快照 key、指纹、观察时间和生成元数据 |
| SourceEvidence | `knowledge.source_evidence`，记录原文章引用对应的文件位置、内容指纹和快照关系 |
| TopicEvidence | `knowledge.topic_evidence`，记录主题、证据、背景/支持/反驳类型、说明、人工核对状态及人员 |

快照行 ID 沿用原 build UUID，以保持构建到快照的一对一映射；原 provenance 的内容快照 key 单独保留。相同输入被不同生成任务读取时允许有多个捕获记录，不把它们误当成多次源码变化。证据以原 article ID 与引用序号唯一，重复捕获不新增或改写记录。相同文件在不同文章中引用时分别保留，因此证据数量不是去重后的业务事实数。

新构建在 `ready` 事务中同步捕获快照和证据；失败或仍在构建中的任务不会提供可用快照。触发器和捕获函数使用调用者权限，索引进程仍受项目 RLS 约束，没有 SECURITY DEFINER 权限提升。手工发布不伪造源码快照，继续保留文档已有的来源记录。

快照/证据仅授予索引角色 SELECT/INSERT，不授予普通应用或索引角色 UPDATE/DELETE。主题关系由知识编辑者维护，版本冲突返回 409；读权限复用 `source.read`。复合外键同时约束组织、项目、原构建、文章和主题，阻止跨项目拼接。关系变更写员工审计。

## 历史迁移

迁移在同一事务中为旧的 ready/extractive 或 ready/model 构建建立映射，保持原来源、构建、文章 ID、正文及活动发布指针不变，不自动发布或撤下资料。

- 原记录缺少观察时间、内容指纹等信息时，显示未知或 legacy；不以迁移时间补造原始观察时间。
- 无效行号、错误的来源 ID、与构建不符的 revision/snapshot 引用不进入证据表；快照详情显示原引用总数与成功映射数量之差。
- 非数组 refs 没有可枚举引用，不从正文推断来源。迁移不会把文章正文当作原始代码证据。
- 已完成捕获不会因重复调用而追加或覆盖；失败由事务回滚，不产生半成品快照。

升级会扫描已有就绪构建及引用，需在部署前根据实际数据量演练迁移时长。回退应使用对应版本和隔离备份恢复，不在运行系统中直接删表。

## 接口

路径省略 `/operator/projects/:key/knowledge`：

| 接口 | 行为 |
| --- | --- |
| `GET /snapshots?offset=0` | 每页 50 个固定快照和引用数量 |
| `GET /snapshots/:id?offset=0` | 快照元数据、来源状态、每页 50 条文件依据；部署版本明确为未知 |
| `GET /topics/:id` | 额外返回最近 200 条直接证据关系，并提示截断 |
| `POST /topics/:id` | 增加 evidence-link/evidence-unlink；需主题 version，关联需类型、说明及明确核对状态 |

员工会话、项目授权、写入 CSRF 与数据库 RLS 继续生效；客户 API 不新增内部证据字段。
