# 第八轮：真实业务接口与失败上下文

本轮范围为审核 POST 查询、SDK 语义事件、问题上报快照、工程视图及 trace 关联，未增加数据库迁移。开发前基线为 `d909010`，历史能力继续接受完整回归。

## 验证场景

- 真实 Fastify + SaaS SQLite + PostgreSQL/OPA：Alice、同租户 Bob、另一租户 Nina 调用同一个 POST 查询，按各自授权返回；未批准字段不返回。
- POST 未审核、错误方法、GET body、额外/复杂参数、危险参数名、角色撤销和能力禁用均拒绝。模拟网络失败验证只发送一次；GET/POST 共用超时、大小限制、重定向拒绝和字段投影。
- Owner 审核接口拒绝客户凭据；配置保存保留容器地址、POST 方法、审核标记和 body 参数。
- SDK 事件不立即联网，最长 10 分钟、最多 5 条；成功事件使旧失败失效、实体变化/clear/destroy 清理，调用者修改对象不污染缓存。
- 失败线索触发支持预览而不调用模型；陈旧、过早时间戳、不同对象和已恢复事件不误触发。
- 预览快照可显式提交，省略 context/capture；工单持久化后客户跨租户不可读，Owner 跨项目不可读。
- `test:observability` 以业务事件承载 traceId，验证真实 Loki 查询、Prometheus 失败/恢复、持久任务与客户安全摘要。

自动测试使用本地合成业务数据，监控验证使用真实组件及合成故障；目标 SaaS 的接口只读性、实时对象授权、模型质量和线上日志完整性仍需单独验收。

## 本地验收结果（2026-09-17）

- `pnpm check` 通过：格式、类型、构建、69 项单元测试、发行文件检查；SDK 与可选浮窗 gzip 12,920 字节，低于 15 KiB 限额。文档校验覆盖 27 篇、178 个本地链接。
- `pnpm test:integration`：22 个文件、167 项测试通过。修正 Registry 测试的 Worker 抢占：进程内测试 Provider 执行期间暂停合成演示 Worker，清理后恢复。
- `pnpm test:observability`：真实 Loki 写入与查询、Prometheus 抓取、事件 trace 关联、客户摘要隔离、三类异常合并以及故障恢复全部通过。该验收与会暂停 Worker 的集成测试必须串行运行；已有合成测试积压先通过正常 Core 调度处理后再验收。
- 浏览器：Alice 通过“按状态筛选订单 → 已完成”查得 ORD-1001；只读 POST 定义修改后审核勾选重置，无效 JSON 无法提交，审核成功后候选仍关闭。
- 浏览器：模拟业务错误 → “为什么不行” → 编辑标题与描述 → 核对事件和脱敏截图 → 提交，Owner 收件箱显示相同对象、错误码、时间与 traceId。数据库中的事件与预览一致，Worker 报告包含对应 Loki 证据；标记的私密文本未进入采集内容。
- 浏览器：取消附带后提交第二张工单，数据库断言 `context = {}` 且没有 capture。明确“上报一个问题”的无模型路由也加入回归；询问“如何上报问题”仍进入知识解释。
- 本地知识库：从 10 份公开文档生成并发布 73 条原文条目，其中 6 条来自语义上下文指南；正文和行号逐条与来源核对。模型调用为 0，不构成真实模型回答质量验收。
- 升级前已备份本地数据与配置。Core、Worker、示例 SaaS 使用 0.8.0 本地镜像，迁移仍为 001–009；已有知识、配置与业务数据保留。

GitHub 上同一提交的 `checks` 工作流还会从干净环境验证依赖审计、OPA、恢复、完整客户旅程和监控链路；以该提交的实际 CI 结果为准。

## 已知边界

普通对话刷新后仍重置。独立支持页只交接身份，未自动继承宿主事件。SDK 事件只存在于内存，提交工单后才持久化，持久工单暂未提供独立事件 TTL 删除。事件和 Trace 标识是未验证线索，不能用于授权或自动证明根因。
