日期：2026-09-19。修改正式 `/admin`、客户知识阅读页、Core API 和 PostgreSQL；新增迁移 `015_knowledge_topics.sql`。本轮在隔离数据库验证，活动环境未迁移或重启。

## 客户引用隔离

客户文章、目录和搜索统一使用不包含源码 commit 的 `publication-<build UUID>` 作为发布标识。文章 `id` 与 `knowledge://` 引用地址保持兼容；旧 `references` 字段继续返回空数组，SDK 旧调用方不需要读取新的必填字段。客户页面展示文档编号和发布标识，员工文章详情继续保留路径、行号、源码版本和生成来源。

历史工单读取时，IndexedKnowledgeProvider 按当前项目/租户权限查找原文章 ID，重新生成安全引用。Knowledge Binding 与 Gateway 使用经复核的投影，不再把旧的摘要或源码版本直接返回；原始存储和审计没有改写。旧文章被替换、来源被禁用或权限收紧时，不返回该引用。

这个边界处理的是 API 引用元数据，不会自动净化已经发布的标题和正文。原文模式的候选标题可能带文件名，转为客户版时应修改；编辑表单已明确提醒审核标题和正文中的文件路径、代码及业务敏感信息。空引用字段不能代替内容审核。内部版本派生独立客户版本的专门流程仍待补齐。

## 正式知识地图

知识中心默认进入“知识地图”，原有“知识目录”、来源、草稿和审核页继续保留。

1. 知识编辑者创建业务域和稳定主题，填写适用范围及需要的文档层次。
2. 将主题标为待确认、已确认或已排除，支持之后修改；排除仅改变整理范围，不撤下已有发布。
3. 关联多份已有文档；扫描候选先转成草稿即可关联，人工业务资料也能关联。点击文档进入原有编辑、审核、证据和历史页面。
4. 逐层展示内部和客户文档的有效发布状态。覆盖查询使用已发布文章的分类与受众；修改新草稿不会把原有发布错误计入另一层或另一受众。
5. 移出主题不删除文档，撤下文档使相应发布缺口恢复。主题和关联刷新后可读。

本轮主题是员工维护的知识目录，尚不代表系统已经自动理解业务。没有模型生成主题或“理解百分比”。同一文档允许关联多个主题，关联只是归类，不改变正文和审核结论。

## 存储与接口

`knowledge.topics` 保存业务域、名称、说明、确认状态、文档层次、版本和操作者。`knowledge.topic_documents` 保存主题和文档关联，通过包含组织/项目的复合外键阻止跨项目关系。

下列路径省略 `/operator/projects/:key/knowledge`：

| 接口 | 行为 |
| --- | --- |
| `GET /topics?offset=0` | 每页 50 个主题，返回下一页位置；按业务域、名称、ID 排序 |
| `POST /topics` | 知识编辑者创建主题；记录审计 |
| `GET /topics/:id` | 主题、关联文档及全量有效发布的覆盖矩阵 |
| `POST /topics/:id` | save/link/unlink，必须携带当前 version；冲突返回 409 |

读权限复用 `source.read`，写权限复用 `knowledge.edit`；独立员工会话与数据库 RLS 同时约束。客户不能查询主题或关联表。所有修改记录真实员工审计。主题详情最多展示 200 份文档并提示截断；关联下拉框沿用工作空间前 200 份文档，完整关联搜索待补。
