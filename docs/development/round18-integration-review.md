# 第十八轮：新系统试接前复核

本轮检查 2026-09-22 的 `main`，起点为 `d533825`。版本仍为 **0.8.0 集成预览**，无新增数据库迁移；本轮不升级活动实例，也不代表外部 SaaS 已完成验收。

## 发现与修复

1. **接入资料落后于源码。** 接入任务书仍称普通聊天刷新丢失、员工只能用本地工作台；运行综述仍停留在迁移 009，后台指南遗漏工作日历、候选评测和历史引用。现统一到迁移 036 的真实实现，补充独立员工账号与租户授权、知识 Worker 容器路径、私有 Git、Tempo、部署证明和可选进阶合同。历史开发记录保留原轮次证据。
2. **复用实例存在配置裁剪风险。** `deploy:prepare` 的单项目发布会移除其他活动项目配置。任务书现在明确区分专用与复用实例，要求先核对已有配置；多项目实例沿用完整项目配置维护流程，不照抄单项目裁剪命令。
3. **SDK 身份切换的异步边界。** 获取 Token 期间销毁实例后，自定义传输仍可能收到请求；忽略 AbortSignal 的传输也可能返回旧身份响应。请求在取得 Token 后及解析响应后再次检查销毁信号，阻止旧请求继续。回归覆盖这两种延迟场景。
4. **上次远端 CI 的清理竞争。** [运行 35484303382](https://github.com/LoganLiu92/agent18/actions/runs/35484303382) 的 232 项断言通过，但删除 Operator 测试库时出现未捕获 `57P01`。当前 `pg-pool` 的 `end()` 完成不代表所有底层连接已结束，`DROP DATABASE ... WITH (FORCE)` 会与关闭中的连接竞争。测试清理改为普通 DROP，允许 PostgreSQL 等待连接结束，真实连接泄漏仍会失败；隔离备份测试采用同样处理，并纳入 CI。
