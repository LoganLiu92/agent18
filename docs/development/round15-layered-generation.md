# 第十五轮：固定原文、分层生成与独立客户知识

本轮把现有正式 `/admin` 知识中心串成可操作闭环：连接来源 → 扫描 → 主题确认及证据核对 → 分层候选 → 审核草稿 → 内部发布 → 独立客户稿及审核发布 → 来源更新检查。不是独立 HTML 原型。实现包含迁移、受控 Worker、Operator API、正式页面和隔离验收。

## 已实现

- **固定原文**：新扫描将模型/提取器实际读取的标准化片段写入 `knowledge.source_fragments`，保留扫描构建、路径、行号和 SHA-256。仅 building 阶段允许索引器写入；应用不能增改，索引器不能更新/删除。读取时重新计算指纹。旧快照无原文明确 unavailable，不用模型文章或当前工作目录补造历史。
- **分层生成**：主题需已确认，选择人工确认的直接证据和所需知识层次，可跨来源。创建任务时冻结主题修订、证据原文、关系说明和分类。最多 12 条证据、100000 字符、6 类文档、一次模型调用，5 分钟任务时限。凭据检测、引用白名单、输出分类和长度校验在服务端执行。
- **持久任务**：PostgreSQL 队列、排他领取、租约、取消、失败码和历史分页。失去编辑权限的员工不能继续生成。完成写入与员工授权修改串行复核。Worker 中断超出租约后标为明确失败，不自动重复计费。重新生成按当前主题及选定证据创建新任务。
- **生成结果不发布**：任务结果包含候选正文、引用、模型标识、提示词指纹、调用次数、已返回的 token 数和待补充项。编辑者逐篇导入内部草稿；同一候选重复导入返回同一文档，不覆盖人工修改。主题定义或证据关联版本已变化时，未导入候选被拒绝，须重新生成。
- **独立客户稿**：从已审核或已发布内部文档创建，客户标题/正文需要重新填写。保留父文档及修订、内部审核依据、主题归类；客户稿独立提交、审核、发布。文档受众创建后固定，不能通过编辑或恢复历史改变受众。内部文档出现新修订时，客户稿显示复核提示。
- **来源新鲜度**：文档逐条与该来源最新完成扫描比较路径/内容指纹，标记一致、变化或移除、未知。即使新版本插入行导致位置移动，相同路径及片段指纹仍可判为一致。未扫描的仓库变更和实际部署状态不在结论内；提示不自动修改或撤回发布内容。

所有入口继续执行员工账号、项目权限、CSRF 和 RLS。客户 API 不返回新内部证据/任务表；客户阅读仍只走已发布知识的安全投影。

## 接口与页面

省略路径前缀 `/operator/projects/:key/knowledge`：

| 接口 | 行为 |
| --- | --- |
| `GET /evidence/:id/content` | 校验并读取固定片段；历史缺原文返回 unavailable |
| `POST /topics/:id/generate` | version、categories、evidenceIds；冻结输入并排队 |
| `GET /topics/:id/generations?offset=0` | 任务历史，每页 20 条 |
| `GET /generations/:id` | 任务、固定输入、结果及已导入文档 |
| `POST /generations/:id/cancel` | 取消排队或运行任务，迟到结果不能覆盖取消 |
| `POST /generations/:id/import` | index；幂等导入内部审核草稿 |
| `POST /documents/:id/customer-draft` | version、title、body、category；独立客户稿 |
| `GET /documents/:id/freshness` | 最多 200 条依据的新鲜度与截断提示 |

知识主题详情可选择依据和层次、观察任务、取消、预览候选、导入；证据链及生成文档提供固定原文核对。文档详情提供客户稿创建、衍生来源提示和来源更新检查。发布覆盖矩阵只计算实际有效发布，生成完成或导入均不算覆盖。

## 运行与升级

1. 停止旧知识 Worker，在隔离备份上演练 001–017 迁移后再升级实际环境。017 新增片段/生成任务表及文档衍生字段，不修改旧正文或活动发布指针。新 indexer 依赖 017；应用和 Worker 需同版本部署。
2. Worker 仍由 `pnpm knowledge:worker` 启动，读取部署者的 `.local/indexer.json`、项目配置及 `.local/model.env`。生成使用已有模型配置；未配置模型时任务明确失败 `MODEL_NOT_CONFIGURED`，不会假装完成。
3. 来源扫描仍需要部署者通过 `AGENT18_KNOWLEDGE_ROOTS` / `AGENT18_KNOWLEDGE_GIT_HOSTS` 设置允许位置（JSON 数组）。生成只能读取员工已选定的固定输入，不增加任意文件访问。
4. 单轮处理用 `pnpm knowledge:worker --once`，每轮至多一个来源任务及一个分层生成任务。持续运行应由部署者进程管理器守护。此次未给运行中的 Docker 服务自动增加进程或注入配置。
5. 旧来源需要重新扫描才具备可验证原文。构建签名升级，`skipUnchanged` 不会继续复用缺原文的旧构建。

新表包含内部源片段和模型候选，应随现有数据库备份、恢复和访问控制管理。源片段存储增加磁盘占用；自动保留/清理策略尚未实现，不自动删除仍被审核知识引用的证据。

## 验收范围与未完成项

本轮验收使用临时隔离数据库、真实迁移/索引器/Operator 路由及受控测试模型；测试模型只验证合同、状态流转和权限，不能证明真实模型生成质量。隔离验收 65 项通过，覆盖 001–017 迁移、历史无原文、新扫描不可变片段、跨项目/客户不可见、正确与错误引用、模型未配置、运行中取消及迟到响应、中断租约、人员撤权、主题变更拒绝导入、重复导入幂等、独立客户审核及内部新修订提示。额外用源码 10 MB 与业务说明 20 MB 两个实际扫描快照验证跨来源输入、支持/反驳关系、双来源引用保留和草稿隔离；没有把合成模型结果当作真实冲突识别质量。篡改保存原文会在 API 读取及创建生成任务时被指纹校验拒绝。

浏览器使用临时隔离环境，实际执行：建立确认主题 → 读取归档片段 → 保存人工证据关系 → 入队 → 测试 Worker 生成 → 候选预览 → 导入草稿 → 审核并内部发布 → 编写独立客户稿 → 再次审核发布。刷新后数据保留。验收发现并修复了导入后列表未刷新、React 同级 key 重复造成提示重复、旧引导文字未更新的问题。桌面及 390 像素窄屏检查通过，内容宽度等于可视区域，无页面横向溢出，浏览器 error 日志为空。

`pnpm check` 的类型、构建、文档链接、格式、普通测试与发行检查通过；普通测试 77 项通过，116 项集成测试默认跳过，未计为通过。真实模型、真实代码库、实际生产迁移及线上业务验收没有在本轮执行。临时预览进程、预览页面及其隔离数据库已清理；既有运行环境未重启或迁移。

自动产品范围识别、主题合并、完整发布集合合同、批量发布、知识冲突处理台、黄金问题回归、私有 Git 凭据管理、网站/PDF 上传解析、真实项目接入仍待完成。工单正式工作台、长期会话、员工租户授权、Insights 和线上日志联调也不因本轮知识流程完成而视为交付。旧 `/console` 演示能力与新 `/admin` 正式能力分别验收。
