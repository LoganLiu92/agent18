# 第十六轮：正式支持工作空间与持续维护

日期：2026-09-20。开发直接进入 Agent18 Console、Server、SDK、存储和部署脚本。保留之前独立账号、来源证据、分层生成与审核发布的实现，没有创建替代性的静态原型。

## 已实现的完整路径

| 工作面 | 页面及行为 | 服务和数据 |
| --- | --- | --- |
| 客户持续对话 | 浮窗刷新恢复、历史/新建/重试；门户历史知识问答 | Conversation、Message、CaseLink；完整项目/租户/用户 RLS、序号及幂等 |
| 工单 | 队列筛选、三栏详情、分配、公开回复、内部备注、历史分页、解决与重开 | 保留 Case 模型，新增七状态、优先级、负责人/团队、版本及事件 |
| 处理闭环 | 解决说明、公开结果、内部知识草稿、重开提醒复核 | 工单修订绑定草稿；客户稿独立审核；来源工单复核信号 |
| 跟进 | 优先级 SLA、暂停/恢复、首次回复；个人站内更新 | 服务器计时、已读版本与实时租户授权 |
| 运行调查 | 工单内工程证据与全项目调查队列，配置状态、报告、显式重新调查 | 复用现有 Observation/Run/Evidence；工程角色、任务预算与幂等 |
| 洞察 | 真实支持指标与每日趋势、个人报告保存/读取/导出/删除 | 固定聚合口径、当前 RLS、原授权范围重新校验 |
| 业务分析基础 | 已注册查询显示指标定义、时区、单位及日期范围 | MetricDefinition；批准字段绑定；日期/窗口在出站前校验 |
| 知识维护 | 来源影响、工单重开影响、冲突登记/人工裁决、检索评测 | 固定来源证据、冲突事件、评测问题及运行快照 |
| 来源日常管理 | 编辑连接及扫描范围、来源/候选分页 | 乐观版本锁、活动任务保护、任务配置快照；旧证据保持原版本 |
| 数据生命周期 | 保留策略页面、客户删除对话/采集附件 | 五类策略、删除账本、预览/显式执行维护脚本、恢复时重新擦除 |
| 部署恢复 | 独立知识 Worker 纳入 Compose，恢复旧库升级、撤销会话、重放删除 | 索引器最小配置，停止旧消费者后才允许激活新库 |

后台支持范围必须显式授权，管理员无默认跨租户工单读取。客户、员工、知识索引器和迁移身份继续分离。内部备注不成为客户消息，工程证据不因客服回复权限而可读；历史文本不触发业务动作。

迁移 018—026 新增以上数据结构；此前 010—017 仍由独立账号和知识链路使用。未修改已发布版本号，未将工作区代码自动部署到正在运行的正式或演示实例。

## 验证和发现的修复

- 隔离 PostgreSQL 验证账号、会话、角色/租户撤权、工单版本冲突、公开/内部消息、幂等、解决/重开、知识回流、支持指标对账、报告授权、保留策略和删除传播。
- 客户 HTTP 测试验证持久对话、同键重试、不同内容冲突、跨用户/跨租户拒绝和删除；SDK 测试验证失败后使用同一键重试、恢复文本不会执行业务工具。
- 评测测试覆盖内部资料拒绝、公开命中、发布撤销、历史结果冻结、归档版本和跨项目；指标测试覆盖日期/窗口在上游请求前拒绝和受控响应元数据。
- 来源维护测试覆盖活动任务拒绝、版本冲突、改权限拒绝、配置快照和标识不可变；Worker 原有固定证据、取消、失败及生成测试继续运行。
- 独立备份测试真实执行 `pg_dump` / `pg_restore`：017 旧结构升级到当前迁移、恢复后正文删除不复活、删除账本回写、SQL 特殊字符、活动消费者阻止激活、临时配置切换。所有目标库随机命名，结束删除本次生成的数据库和配置，未切换活动部署。
- 浏览器使用隔离数据库及合成账号，走通工单公开回复/内部备注/解决/知识草稿/重开/影响提醒、支持报告保存、来源连接/扫描/编辑重新扫描及候选读取、客户浮窗刷新恢复、独立门户身份交接及继续问答。桌面和 390 像素窄屏核验；发现并修复提交后残留文本、旧调查内容闪现、消息历史只读最早一页、工单关联与对话保存竞态。
- 部署配置测试检查索引容器只持有必要项目身份及 indexer 凭据；Compose 配置解析、类型、格式、SDK 体积和公开 API 合同检查纳入整体回归。

最终本地结果：`pnpm check` 全部通过（80 项普通测试，126 项需要独立环境的测试默认跳过）；隔离数据库选定回归 85 项通过；独立备份/删除传播测试 1 项通过。公开 API 合同 30 项，SDK gzip 14,491 字节，符合 15 KiB 预算。

使用单独测试镜像 `agent18:workspace-support-qa-20260920` 实际构建并完成全新 Compose 安装旅程：26 项迁移、Core/执行 Worker/知识 Worker 启动、独立 SaaS 查询隔离、预览确认与回读、真实 Worker 排查、备份恢复、停止旧消费者后激活新库，以及切换后的新任务处理均通过。测试结束清理其容器、卷和网络；保留原活动部署。模型未配置，旅程验证的是确定性流程与原文检索。

可重复命令：

```sh
pnpm check
pnpm test:operators
pnpm test:backup:isolation
```

`test:operators` 自建临时库但依赖本机 PostgreSQL/OPA；`test:backup:isolation` 使用现有本地 Compose PostgreSQL，只备份并恢复它生成的测试库，不暂停活动应用。不要将旧 `test:recovery` 的停服务行为与本次隔离备份测试混淆。

## 能力边界

当前 SLA 使用连续时间，尚未加入工作日历；站内提醒不等于邮件或第三方通知。客户持久化的是已确认保存的文本，不是完整业务卡片/附件归档，也不承诺页面关闭前未确认写入的数据。

检索评测是公开来源 Top-5 命中回归，不能代替 20 道真实业务黄金题和模型语义审查。源码/文档扫描与确定性测试使用隔离样本；未拿它们代替模型生成质量、真实员工交付或客户业务验收。

业务分析保留受控 Query/Policy 和指标合同，后台当前实际统计来自支持工单。真实销售、转化、退款口径及定时报表需要目标数据源；外部工单同步、特定 Trace 平台、可信部署/commit 映射、第三方文档 OAuth、自动领域识别与多场景 Playbook 尚不属于已验证的运行能力。

保留清理默认预览，只有 `pnpm retention --apply` 执行。本地删除不远程撤回已送往模型/日志提供方的资料，也不自动删除人工重新整理发布的知识。恢复删除传播依赖当前数据库的删除账本；整库灾难需配套异地备份和最新删除账本保全。

入口、使用步骤和部署配置见[正式后台指南](../guides/support-workspace.md)。后续按[任务状态表](../planning/support-and-insights-work-packages.md)选择真实适配，不能把没有凭据、没有实际数据的连接器展示成已接通。
