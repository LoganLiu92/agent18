# 第十二轮：正式来源向导、扫描任务与修订审阅

本轮继续修改 `/admin` 正式 React 应用、Core API 和 PostgreSQL；没有独立 HTML 或模拟任务。适用开发版本，新增迁移 013 / 014。现有运行环境未执行迁移或重启。

## 可操作流程

1. 管理员选择项目 → 知识中心 → 来源与版本 → 连接知识来源。
2. 三步填写来源名称 / 标识、目录或 HTTPS Git 地址、版本、包含 / 排除规则、生成方式。
3. 保存连接及排队任务。任务未领取时明确显示“等待索引进程”；取消、失败、重试均持久化。
4. 独立知识索引进程领取任务，固定扫描版本，生成原文分类或模型整理结果。任务本身不发布知识。
5. 查看扫描结果、读取正文及文件路径 / 行号，将有用的候选转成内部文档草稿。重复导入同一候选返回原草稿。
6. 编辑并审核，明确受众后发布。候选来源证据会进入文档和最终已发布文章，来源版本与线上部署版本继续区分。
7. 文档历史可以并排查看正文、标题、分类与受众。恢复历史创建新草稿，不覆盖原发布。退回审核必须填写原因。

来源和扫描数据存储于 `knowledge.connections` / `control.knowledge_jobs`；任务状态为 queued / running / succeeded / failed / cancelled。默认来源受众固定 internal，客户化在文档审核阶段处理。

## 索引进程启动

Core 继续使用应用数据库角色，不加载索引数据库凭据，也不读取来源目录。部署者在能访问来源的机器上运行知识索引进程；该机器需有项目配置、`indexer.json` 和数据库连接。

```sh
# 先在目标部署环境执行迁移并构建；示例路径须替换为实际允许的只读资料目录。
AGENT18_KNOWLEDGE_ROOTS='["/srv/knowledge"]' \
AGENT18_KNOWLEDGE_GIT_HOSTS='["github.com"]' \
pnpm knowledge:worker
```

这两个变量为 JSON 数组，默认空，表示不允许读取任何目录或 Git 主机。目录经真实路径校验，不允许跳出允许的根目录；Git 仅接受 HTTPS、允许主机、默认 HTTPS 端口，不接收地址内的用户名 / 密码 / Token。

`--once` 只处理一个任务，适用于受控运行或验收：

```sh
AGENT18_KNOWLEDGE_ROOTS='["/srv/knowledge"]' pnpm knowledge:worker --once
```

可通过 `AGENT18_LOCAL_DIR` 指定部署配置目录。模型模式使用进程环境 / 默认 `.local/model.env` 中的既有模型配置，默认原文模式不调用模型。模型模式每次任务最多 100 次调用；向导说明资料出站和调用成本。

索引进程通过数据库租约领取任务，多个进程不会同时领取同一个任务；同来源构建另有现有 advisory lock。35 分钟租约超时后标记失败，任务执行有 30 分钟截止。工作人员须主动重试，不自动重复长任务。运行中每 1.5 秒核验取消状态和发起人管理权限；停用或撤销管理员后终止扫描。读取和构建的失败信息只返回稳定错误码，不回传原始异常、地址或凭据。

进程仍需由部署者启动和托管，当前 Compose 未自动新增服务；本轮没有承诺“一次部署后索引进程自动运行”。私有 Git 的专门凭据绑定界面尚未实现；现有 Git 读取行为依赖部署环境，须单独验收。

## 接口与权限

下列路径省略 `/operator/projects/:key/knowledge`。均使用独立工作人员会话、Origin 和写入 CSRF；每次数据库操作重新验证权限。

| 方法和路径 | 实际行为 |
| --- | --- |
| `GET /connections` | 已保存来源的脱敏摘要和最近任务；最多 201 条，前端提示截断 |
| `POST /connections` | 管理员保存不可变来源配置及第一项扫描任务 |
| `POST /connections/:id/scan` | 管理员重试；有待执行任务时返回已有任务 |
| `POST /jobs/:id/cancel` | 管理员取消排队 / 执行中的任务 |
| `GET /builds/:id` | 来源访问角色读取候选正文、证据和跳过文件；最多 100 篇 |
| `POST /articles/:id/draft` | 知识编辑人员将候选和证据转成内部草稿 |
| `GET /documents/:id/revisions/:version` | 来源访问角色读取指定不可变历史快照 |
| `POST /documents/:id`，action=restore | 知识编辑人员基于历史版本创建新修订 |
| 同上，action=return | 发布人员填写 reason 后退回精确版本 |

`connections` 不返回 spec/location 给普通来源查看页面。索引角色只能在指定项目 scope 读取来源配置；任务调度元数据由专用索引角色跨项目领取。一个受限制的数据库函数只返回任务发起人是否仍可执行管理任务，不授予索引角色读取账号密码表的权限。

旧 CLI watch 现在排除后台人工来源及后台连接来源，避免把“不在 knowledge.json 中”误判为删除来源而撤下这些知识。

## 当前限制和下一项

- 连接尚不能原地编辑 / 删除；需要改变扫描定义时创建新标识。来源扫描结果不自动合并到此前人工编辑的文档。
- 本轮是来源、扫描、候选、审阅的可用流程，尚不是完整 Topic / Evidence 知识地图；业务范围确认、跨来源冲突、新鲜度依赖图和增量更新仍待实现。
- 暂无文件上传、Notion / Confluence / RAGFlow 连接器、Git Webhook、密钥引用管理或后台模型配置。
- 文档并排对照不是逐字差异高亮；没有直接回滚线上发布，历史恢复必须重新审核。
- 全量分页和任务历史详情待补；列表明确限额。工单 / 运行 / Insights 正式员工工作台仍待接通。

## 验证

随机隔离数据库执行全部 001–014 迁移，现有安全、知识和实体测试共 59 项通过。来源流程验证允许目录之外拒绝、失败重试、完成构建、跨项目拒绝、候选不对客户可见、重复导入幂等、证据保留到发布、取消和 CLI watch 排除。修订测试验证历史不变、恢复回到草稿、退回原因必填及角色隔离。

浏览器已操作三步连接向导 → 队列 → 独立进程实际扫描 → 查看正文与行号 → 转入草稿，并验证退回原因保存和历史恢复新修订。未调用真实模型，未连接外部私有仓库。

这些是本地隔离验证，不等于私有 Git、真实模型出站、正式部署或目标网站业务验收。
