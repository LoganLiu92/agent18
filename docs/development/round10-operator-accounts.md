# 第十轮：独立账号运行闭环

日期：2026-09-19。开发包：A01 页面验收、A02 账号恢复/审计/分页与公共权限服务。以下已在本地工作树实现并验证，尚未向活动 Demo 应用迁移或发布新版。

## 交付

- 本地 Setup 的管理员恢复表单：两次输入用户名，只恢复已有管理员，启用账号、重置临时密码、撤销旧会话、首次登录再次改密。审计记录部署者本地恢复，不冒充员工。
- 工作人员按用户名/显示名称、启用状态筛选，20 条一页、游标加载更多；权限/密码修改成功有反馈。
- 管理员操作审计页：操作类型筛选、游标分页、实际操作者、目标账号、时间及请求编号。普通工作人员不可访问，数据库应用角色不能修改或删除审计。
- 公共 `withPermission`：在短事务中重新检查当前会话、强制改密状态、项目成员和具体能力；与权限变更串行，已撤销的旧会话对象不能继续授权。
- 迁移 011 为审计分页和筛选增加索引。
- 备份恢复与激活前清空恢复库的员工会话并追加维护审计；保留账号、授权和历史审计，兼容没有账号表的旧备份。
- 新增[账号使用与恢复指南](../guides/operator-accounts.md)和 `pnpm test:operators` 独立测试入口。

最后仅增加保存成功提示后重新通过类型/构建和文档检查。真实备份演练使用 `.local/operator-restore-verify.ts` 临时验收脚本；备份源为本轮合成预览库，激活只修改临时配置目录。没有重启活动 Core/Worker，没有把恢复库接入实际网站。

拒绝路径包含：外部地址/Origin 或无 Owner 访问码的恢复请求、试图恢复普通工作人员、确认用户名不一致、客户凭据进入员工接口、无 CSRF 写入、跨项目访问、编辑者发布/配置来源、撤权后复用旧会话、工作人员读取管理审计、应用角色删除审计。

## 已知边界与后续

A02 的账号维护闭环已具备本地验收证据。公共权限服务目前只接入现有项目/账号入口；知识中心和工单的实际 API 必须在各自开发包中接入并验证，不能据此宣称其权限已完成。部署级短事务锁先保障正确性，多实例吞吐优化另行验证。

当前管理审计不包括失败登录列表或授权前后差异。账号备份恢复仍须核对备份后发生的停用/撤权；清除会话不能代替恢复后的人员复核。

下一开发包为 K01：知识 Topic、SourceEvidence、DocumentRevision、Publication 模型及旧数据映射，交付可读的主题目录和详情，再推进 K02 的来源连接与可恢复扫描。
