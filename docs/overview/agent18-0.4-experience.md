# agent18 0.4：安装、网站入口与业务执行机制

agent18 是面向已有 SaaS 的开源支持与业务助手。它读取已有代码和文档，生成可发布的知识；使用部署者自己的模型；从 SaaS 接收当前用户的短期身份，在权限范围内提供答案、支持任务和已注册的业务操作。0.4 在 0.3 核心能力上补齐了安装向导、浮动入口和独立支持页。

## 从部署到客户使用

| 阶段 | 当前实现 | 实际产物 |
| --- | --- | --- |
| 安装 | `pnpm start` 启动 PostgreSQL、OPA、Core、Worker、示例 SaaS 和本地配置服务 | 保留于 `.local` 的配置、持久化数据库、公开产品首页 |
| 初始化 | 五步向导配置系统身份、模型、知识与网站入口 | 项目/租户、公钥和站点配置、模型环境文件、接入代码 |
| 知识生成 | 本地目录/Git 读取、过滤、分块，原文或模型整理 | 六类知识条目，文件/行号/版本引用，构建报告 |
| 知识发布 | 按来源检查、发布和撤下，数据库执行受众与租户隔离 | 客户只能读取已发布且有权访问的版本 |
| 网站接入 | SDK 浮动入口、嵌入区块、独立支持页 | 原网站内的帮助入口及共享当前身份的支持页面 |
| 客户提问 | 搜索或模型生成带引用回答；模型不可发起工具写入 | 原文证据或可溯源回答 |
| 业务操作 | 表单/模型规划、预览、确认、SaaS 校验、执行、回执 | 以当前用户身份执行的一次操作与审计记录 |
| 支持跟进 | 创建 Case、Run 和事务 outbox，Worker 持久化执行 | 当前用户可查的问题记录、任务结果和证据 |

安装后先进入产品首页，部署者从本机配置入口开始；客户通过接入 SaaS 使用助手。Core 不提供部署配置权限。独立支持页、浮窗和演示客户工作台有不同用途，不能把本地演示身份签发器当作生产登录。

## 三种网站接入方式

**浮动助手**通过 `mountFloatingAssistant` 挂在网站角落。面板包含“找答案、办业务、提问题”三个入口；使用 Shadow DOM 隔离宿主网站样式，支持窄屏、关闭按钮、Escape 返回入口焦点，以及独立页面跳转。它不读取或操作宿主页面的业务 DOM。

**嵌入区块**通过 `mountAssistant` 挂载到网站提供的容器中，使用同样的功能和样式隔离。网站可自定义标题和成功回调；也可以只使用 `Agent18` API，自行编写界面。

**独立支持页**通过 `openSupportPage` 在用户点击时打开。URL 只包含项目、来源 Origin 和随机通道标识，登录 Token 不进入 URL 或浏览器持久化存储。支持页先检查项目允许的来源；双方通过 `postMessage` 同时核对精确 Origin、窗口引用和随机通道。每轮 API 调用从原 SaaS 请求当前短期 Token，并发请求可合并。Core 再验证签名、有效期、项目和租户。原页面关闭或销毁连接后，独立页无法继续取得新身份，需要重新从 SaaS 进入。

宿主系统仍须在退出登录、用户切换时销毁旧 SDK 和独立页连接。真正的权限以每次后端校验结果为准。浏览器拦截弹窗时有明确提示；直接访问没有身份上下文的 `/support` 会提示从 SaaS 打开。

## 代客操作具体怎样执行

当前版本选择 **API 驱动**。前端展示需求输入、业务字段、预览和确认按钮。确认后，SDK 调用 agent18 Core；Core 携带该用户的短期 Bearer Token 调用项目配置中的固定业务桥 URL。SaaS 验证签名和当前用户身份，检查租户、对象所有权、业务状态和幂等键后执行。业务回执返回给 Core，再回到助手和宿主页面。

这条链路仍经过 SaaS 自己的业务规则。完整代码仓库可以帮助理解系统，但不会替代用户授权、绕过对象权限，或让任意源码函数自动变成可调用写工具。

| 执行形态 | 0.4 状态 | 适用方式 |
| --- | --- | --- |
| 服务端业务 API | 已实现 | 显式注册操作、限制角色和字段，使用 prepare/execute/status 合同 |
| 宿主前端成功回调 | 已实现 | 收到成功回执后，由原网站自己的代码刷新业务数据或界面 |
| 自动点击网页/填表 | 未实现 | 后续需要页面适配、执行环境、焦点与并发控制、页面动作策略及效果核验 |
| 任意后端/数据库操作 | 不提供 | 只能调用项目注册的业务桥操作，不执行自由 SQL/shell |

模型可将自然语言整理为候选业务参数。预览保存在数据库，并绑定用户、租户、操作配置和过期时间；确认阶段重新做策略和状态检查。超时或连接不确定时保留 `uncertain`，只允许查回执，不自动重发写请求。成功回调失败也不会把已成功的业务操作改成失败。

示例 SaaS 在独立服务中实现“修改我的通知偏好”：只更新合成用户 Alice 自己的偏好，使用 SQLite 同事务保存业务数据和幂等回执，不发邮件。示例订单表是接入布局展示，助手不会修改这些订单。

## 这轮完成的实现

- 公开产品首页、带部署访问码的五步初始化向导、真实模型测试/保存、项目注册、资料构建/检查/发布、入口代码生成及 Core 配置应用。
- 本地部署配置服务，隔离于客户 Core；配置接口有访问码、本机地址和精确来源校验，敏感值不回显。
- 全新安装预置可运行的演示站点身份范围和通知偏好操作；已有配置升级失败时不再错误地重新初始化密钥。
- 可复用的浮窗与内嵌助手；支持业务预览确认、回执查询、提交问题、宿主成功回调和样式隔离。
- 独立客户支持页，包含知识浏览/提问、业务助手、我的问题和当前身份；使用来源绑定的身份交接。
- 更新示例 SaaS、开源接入文档，以及初始化权限、配置保密、模型连接、知识发布和独立页身份交接测试。

当前仍是开发预览版。未完成真实客户 SaaS 的生产接入验收，也未使用真实供应商 Key 验收模型效果。日志连接器、线上运行时调查、浏览器代点击、自动代码修复和 PR 生成不属于已实现能力。配置向导当前作为宿主机本地工具运行；无后台定时知识同步调度，知识构建由向导或 CLI 主动发起。
