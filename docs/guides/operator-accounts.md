# 独立后台账号与恢复

适用范围：本地工作树中的 A01/A02 实现。需要应用数据库迁移 010、011 并重新构建/启动新版服务；不是 0.8 已发布部署自动具备的页面。独立后台入口为 Core 地址的 `/admin`。

## 首次初始化

1. 按安装指南完成部署和数据库迁移；只对外代理 Core。Setup 维护服务保持监听回环地址。
2. 在部署主机打开本地 `/setup`，使用部署访问码进入。在“连接你的系统”或接入工作台总览找到“Agent18 后台账号”。
3. 创建首位管理员，用户名使用 3—80 个英文字母、数字及 `_.@-`，密码为 15—128 个字符。系统没有默认账号、公开注册或自动生成的通用密码。
4. 点击“打开后台登录”，使用刚创建的独立账号登录。远程部署的 `consoleOrigin` 必须使用 HTTPS；只有回环地址支持 HTTP 开发预览。

账号属于 Agent18，网站客户仍由原网站签发 Support Token。后台 Cookie 不能用于客户业务 API，客户 Token 不能进入后台；不需要接入宿主员工 OIDC/SSO。

## 管理工作人员

管理员进入“工作人员”，创建账号与临时密码，再按项目分配查看、客服、工程、知识编辑或知识发布角色。临时密码经团队已有安全方式交付，平台不会自动发送邮件或消息。

工作人员首次登录必须更改临时密码，改密前不能进入项目或管理页面。账号支持按用户名/显示名称和启用状态筛选，每页 20 条，点击“加载更多账号”继续。列表查询中 `%` 等字符按普通文本处理。

停用、修改权限或重置密码会撤销该账号所有会话；修改自己的权限后需要重新登录。系统阻止停用或降级最后一位启用管理员。会话最长 8 小时，连续 30 分钟无请求失效；重新登录后读取最新授权。

知识中心、工单和业务洞察均按项目角色校验。员工工单涉及租户范围时，还需明确租户授权；项目成员关系不授予所有客户数据访问权。

## 忘记管理员密码

部署者在本机 Setup 工作台展开“忘记管理员密码？从本机恢复”，填写已有管理员用户名、再次确认用户名及恢复用临时密码。

恢复会重新启用该管理员、撤销其旧会话并要求下次登录改密；只能恢复已有管理员，不能把普通工作人员提升成管理员，也不会新增账号。远程请求、错误 Origin 或缺少部署访问码均拒绝。此入口没有发布到 `/operator/*`。

恢复记录的操作者显示“部署者（本地维护）”，不会冒充某位员工。忘记普通工作人员密码时应由管理员在人员页面重置。维护访问码及配置文件本身属于部署凭据，只能由有权维护主机的人保管；不要将 Setup 通过公网代理开放。

## 查看审计

管理员进入“操作审计”，按操作类型筛选，点击“加载更早记录”分页查看。记录包括操作者、目标账号、时间与请求编号，覆盖初始化、创建、权限/状态修改、登录退出、改密、密码重置、本地恢复和备份恢复后的会话撤销。

这不是完整安全事件平台：当前未展示失败登录尝试、权限变更前后差异或宿主业务审计。密码、原始会话 Token 不写入审计。应用数据库角色只能追加和读取该审计表，无更新/删除权限；工作人员不能读取管理审计接口。

## 备份、恢复与升级

数据库备份包含账号哈希、成员关系和审计，配置备份仍按既有运维流程保管。新版 `restoreBackup` 在隔离恢复库清空员工会话，`activateRestore` 切换配置前再次清空；旧备份没有账号表时兼容跳过。账号和历史审计保留，会话撤销追加维护记录。

恢复的是备份时的账号状态与授权。启用恢复库前核对离职/停用人员、管理员、成员授权和需重置的密码；恢复会话失效不能代替这项核对。启动后所有工作人员重新登录。旧版本恢复脚本不具备上述会话撤销行为，应使用新版受验证流程。

本轮验证涵盖恢复清理 SQL、旧表缺失兼容与会话回读，并对合成预览库完成真实 pg_dump/pg_restore 及临时配置激活演练。尚未执行实际网站的生产恢复验收，详见[开发记录](../development/round10-operator-accounts.md)。

## 开发接口边界

- `/operator/session` 提供当前账号、项目和 CSRF Token；所有员工接口返回 `Cache-Control: no-store`。
- `GET /operator/accounts?search=...&status=all|enabled|disabled&after=...&limit=20`，返回账号及 `nextCursor`。分页上限 50。
- `GET /operator/audit?action=...&targetId=...&before=...&limit=20`，返回事件及 `nextCursor`。仅管理员可访问。
- 修改接口继续要求同源 Origin、有效 Cookie 和 `X-Operator-CSRF`。会话 Token 不进入浏览器持久存储或模型上下文。
- 后续 Operator 数据库接口调用 `withPermission(session, projectKey, permission, callback)`，在事务中重新核对会话和项目能力。callback 只做短数据库操作，不能在锁内调用模型、外部 API 或运行长任务。耗时任务先持久化，执行阶段另行核对当前授权。

当前权限锁为部署级、以正确性优先。完整租户工单授权已接入；容量上限仍需按实际数据规模测定。

账号回归执行 `pnpm test:operators`。需要本地配置及可创建测试库的 PostgreSQL 管理连接；测试使用随机命名的独立数据库，结束仅清理自己创建的数据库与临时文件，不对活动库应用迁移。

## 支持数据范围

项目角色以外，“接入配置”还需要明确授予工单租户范围。管理员也没有默认全租户支持数据读取。客服能处理公开回复、内部备注、分配及解决；工程角色才能读取运行证据和创建调查。知识编辑、审核发布仍独立授权。角色或账号状态变更会清理既有租户授权，请重新核对授予范围；保存的洞察报告读取时重新校验范围。完整操作见[正式后台指南](support-workspace.md)。
