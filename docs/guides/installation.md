# 安装与初始化向导

agent18 0.4 将部署配置、网站入口和客户使用流程分开呈现。部署者完成初始化后，客户在原 SaaS 的浮窗、嵌入区块或独立支持页中使用助手。

## 安装并打开向导

需要 Node 24.14.x、pnpm 11.19.0、Docker Compose。Git 知识来源需要部署机器已有的仓库读取权限。

```sh
pnpm install --frozen-lockfile
pnpm start
```

`start` 依次初始化本地配置、构建并启动 Docker 服务、启动本地配置服务。终端显示 `Owner access code`；在 <http://localhost:4321/setup> 输入该访问码。首页 <http://localhost:4318> 也提供向导入口。

| 地址 | 用途 | 使用身份 |
| --- | --- | --- |
| `http://localhost:4321/setup` | 部署者初始化和维护 | 本机部署访问码 |
| `http://localhost:4318/` | 产品首页与入口说明 | 公开，无配置权限 |
| `http://localhost:4319/example` | 独立示例 SaaS 和浮动助手 | 合成用户 Alice |
| `http://localhost:4318/support` | 客户独立支持页 | 必须从 SaaS 通过 SDK 打开 |
| `http://localhost:4318/console` | 本地演示客户工作台 | 本地演示身份签发器 |

已有安装运行 `pnpm setup && pnpm demo:start` 更新应用，再用 `pnpm setup:ui` 打开向导。已有密钥与数据保持原样。较早版本未配置演示业务接口时，可运行 `pnpm demo:actions && pnpm demo:start`；该命令仅用于演示项目。

## 五步完成配置

1. **连接系统**：先体验已有演示项目，或填入自己的项目名、网站 Origin、租户、Issuer 和 Ed25519 公钥集。私钥保留在 SaaS 后端。项目、公钥和租户配置实际写入文件及 PostgreSQL。
2. **连接模型**：填写兼容接口的 Base URL、模型 ID、API Key，测试连接后保存。测试从配置服务发送一次简短请求，可能产生供应商调用费用。留空 Key 保持已有密钥，不会回显。无模型也可以跳过并使用原文检索。连接测试不等于所有模型生成任务已经通过业务验收。
3. **接入资料**：添加本地文档目录或 Git 仓库，选择文件范围、分支及内部/客户受众。首次体验会带入本项目示例资料，保存和构建由部署者主动触发。移除来源或调整受众并保存，会立即撤下旧的已发布内容，历史版本保留；受众变化后需重新构建才能发布。当前向导编辑一个项目的来源清单；多项目可分别维护配置文件，通过 CLI 的 `AGENT18_KNOWLEDGE_CONFIG` 使用。
4. **生成并发布**：启动实际读取与索引任务，查看进度，展开生成的文章和文件行号引用，再按来源发布。构建失败保留之前的发布版本；内部资料始终不会进入客户读路径。重载页面可继续查看当前配置进程中的任务；配置进程重启后以数据库构建记录为准，未完成的构建需重新发起。
5. **放到网站**：选择浮动助手、嵌入区块或独立页面，填写 agent18 对外 Origin 并复制代码。完成按钮保存工作空间设置，并重新创建 Core 容器，使项目和模型环境配置生效；不删除数据卷。失败时会明确提示设置已保存、重启未完成，可排查后重试。

配置可随时返回修改。SaaS 的 Support Token 签发接口、业务桥接口和 HTTPS 反向代理仍由接入方部署；输入完整代码仓库不会自动获得有效的客户身份，也不会自动开放任意业务写接口。

## 本地配置服务的运行机制

配置服务运行在宿主机，仅绑定 `127.0.0.1:4321`，拥有部署账户本来就有的文件读取与 Docker 运行权限。`/owner/*` 同时检查本地来源、精确 Host/Origin 和部署访问码。客户 Core 不注册这些配置接口，也不接受部署访问码作为客户身份。密钥、访问码和数据库配置只保存在被 Git 忽略的 `.local/`，文件默认权限 `0600`。

远程服务器上运行时，先建立到部署服务器的 SSH 本地端口转发，再打开本机 `localhost:4321`；首页的 `localhost` 向导入口指向当前浏览器所在机器。不要将配置端口通过公网代理开放。完成维护后可在运行 `pnpm setup:ui` 的终端按 Ctrl+C 关闭；Docker 中的客户服务继续运行。

本地模型地址要同时适用于宿主机构建进程和 Docker Core。容器中的 `localhost` 指向该容器本身；应为模型配置双方都可达的地址，或分别管理宿主机与容器的部署配置。向导不会自动调整模型服务的网络绑定。

构建任务复用独立 indexer 数据库角色。配置服务不执行知识仓库里的安装脚本、构建脚本或测试代码。最后的应用操作由服务端固定为 Docker Compose 的 Core 容器重建，网页不能提交 shell 命令。

## 页面入口与业务执行

参见 [网站接入](integration.md) 和 [业务接口合同](business-actions.md)。当前链路为：用户提出需求 → 展示操作预览 → 用户确认 → agent18 服务端调用 SaaS 业务桥 → SaaS 校验权限与业务条件 → 返回持久化回执。

前端承担交互和确认，也可以在成功回调中刷新业务页面。当前版本没有浏览器自动点击、任意页面脚本或根据源码自动开放写接口的执行器。
