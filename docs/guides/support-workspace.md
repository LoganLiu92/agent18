# 正式后台：知识、工单、排查和洞察

适用于应用至迁移 036 的当前源码工作区。公开版本标签仍是 0.8.0；页面存在、测试通过与目标站点正式上线是不同状态。基础后台见[第十六轮记录](../development/round16-support-workspace.md)，后续交付与验证见[第十七轮记录](../development/round17-product-workflows.md)。

## 一个成熟网站的接入顺序

1. 按[安装指南](installation.md)部署 PostgreSQL、OPA、Core、执行 Worker 和知识 Worker。在本地 Setup 初始化独立管理员，日常员工进入 `/admin`。不要求接入客户公司的员工 SSO。
2. 建立项目，登记网站 Origin、租户、公钥和身份签发规则。网站客户继续使用原系统账号，经后端签发短期 Support Token；后台员工账号不代替客户身份。
3. 在“接入配置”分配员工的项目角色和明确的租户范围。管理员也必须获得支持数据范围，才可查看工单、排查和统计。知识编辑/发布权限与工程证据读取权限分开。
4. 在“知识中心 → 来源”连接目录或 HTTPS Git，选择范围、版本与生成方式。先原文扫描，再确认主题、关联源码/业务文档证据、生成分层内部草稿，审核发布。客户文档由独立客户稿发布，源码和内部排查信息不会直接进入客户知识。
5. 按[业务查询](business-queries.md)导入并审核允许的只读接口；按[业务办理](business-actions.md)接入预览、确认、回执协议。只有文档、代码和日志不能自动获得订单查询或业务写入权限。
6. 按[监控指南](observability.md)连接 HTTP/Loki/Prometheus，按[进阶合同](advanced-workflows.md)选接 Tempo 和部署证明，配置可信租户映射、日志标签、时间窗、限额和服务端凭据。界面不会把尚未配置的日志或 Trace 显示为已接通。
7. 挂载 SDK 或使用独立支持门户。以两名客户、两名不同权限的员工验证问答、刷新恢复、查询、确认办理、上报、回复、解决、重开、知识回流与跨租户拒绝。
8. 在“洞察”查看有权租户的支持指标，保存报告；业务经营或网站转化指标需再提供实际只读分析接口和口径，不能由工单数据推断销售额。

## 工单日常处理

“客户支持”按租户、状态、优先级、团队、负责人和标题筛选，分页读取。详情展示公开沟通、内部备注、分配、事件历史、业务上下文与解决方案。长沟通和事件有历史分页。

- **公开回复**交付客户；**内部备注**只在工作人员界面可见。工程调查与日志原文需要工程权限，客服角色不能读取内部工程证据。
- 保存状态或分配时校验版本。另一员工已修改时返回冲突，刷新并核对后再操作，避免覆盖。
- 解决工单须填写内部处理说明、客户可见结果和结论等级（假设、证据支持、已核实）。调查结束不会自动解决工单。
- 解决后可将经过整理的内容转成内部知识草稿。同一工单修订重复提交不重复建稿，修改了内容的重复提交会提示冲突；不会自动审核或发布。
- 客户或员工重开后，知识维护页显示相关知识需要复核。知识审核记录当前复核版本，不将历史解决方案直接当作现状。
- 员工账号停用、改权限或撤销租户授权后，后续请求重新校验；已保存报表也不能继续访问被撤销的范围。

SLA 在接入配置启用，按优先级设置目标分钟数，可选择连续计时或带时区、工作时段和休息日的工作日历。解决时限在等待客户、等待内部、已解决、已关闭时暂停，重开继续累计；首次公开回复或公开解决说明停止首响计时，内部备注和等待状态不停止首响。工单保留日历快照，配置变化不追溯重算，详见[完整 SLA 口径](advanced-workflows.md)。

站内更新只显示当前分配给自己的可见工单。标记已读绑定工单版本，新更新仍会出现；外部通知需要另行接入[签名工单桥](advanced-workflows.md)，平台没有开箱邮件或短信通知。

## 持续对话和客户门户

浮窗/内嵌助手将文本消息保存在服务端，刷新恢复最近对话，也可新建、查看历史和删除。`/support` 的“历史对话”读取同一客户范围，支持继续知识问答。

历史消息记录角色、序号、写入时间，以及最多五个知识/查询/提案/工单引用和观察时间，明确属于当时的显示记录。客户端提交的 `assistant` 文本不是服务端证明，不作为工具结果或授权依据。恢复不会重放查询、执行写入、恢复确认按钮，也不会自动把全部历史作为模型上下文。业务卡片、审批和回执仍从各自业务接口读取；历史文本不等于完整卡片归档。

消息按请求键重试，重复不新增；断网时提示“部分消息未保存”，点击重试。只有服务端确认保存的消息具备刷新恢复保证，页面关闭前尚未确认的文本不承诺保留。每段最多 500 条消息，每名客户每个项目/租户最多 1,000 段未删除对话，并有写入频率限制；达到上限需新建或清理。

从对话提交工单后保存关联；删除对话正文不会删除已上报工单。客户可在“我的问题”读取公开沟通及当前已解决工单的公开结果，也可删除自己提交的页面采集附件。

## 知识维护和评测

来源列表及扫描候选支持分页。无排队/执行任务时可以编辑连接，保留来源标识和类型；变更名称、目录/地址、ref、扫描范围或生成方式后会排队新扫描。版本校验拒绝覆盖他人的修改，任务保存本次配置快照，后续编辑不改变旧任务输入或已归档证据。

“来源影响”按文件内容指纹比较当前来源与文档证据，显示未变化、变化或未知；源码变化不等于线上已经部署。“冲突”要求同一规则/适用范围内的两条以上文档或固定证据，由发布者人工裁决并记录原因，不自动修改文档。

发布检索评测使用客户生产检索算法，测试已发布、对全体客户可见的来源，保留问题版本、命中文章和发布版本；撤下来源后再跑会反映缺失，旧评测保持当时结果。Playground 还可评测固定修订的客户候选稿，记录预期答案、必须/禁止引用、不可回答题及人工语义复核；高优先级失败阻止对应文档发布。来源命中率不是模型答案正确率，也不覆盖租户专属知识；真实业务黄金题仍需业务人员标注。具体发布门槛见[知识治理](advanced-workflows.md)。

## 洞察与业务指标

后台支持指标包括创建量、当前积压、状态分布、UTC 每日趋势和已解决样本的平均处理时长。查询明确起止范围、口径版本及样本数，聚合 SQL 在员工当前租户 RLS 下执行。保存时服务端重新计算，存入个人报告；读取时重新校验完整原始范围。可导出聚合 JSON，不包含客户对话、截图或日志正文。

已有 Business Query 可登记 `metric`：指标 ID/版本、定义、时区、数值列及单位/币种、允许维度、起止日期参数与最大窗口。日期使用 `YYYY-MM-DD`，范围为左闭右开，系统在请求上游前校验日期和窗口。上游仍承担实际指标计算、日期过滤和客户对象授权；不能给普通订单接口加个指标标签就声称它提供了正确财务统计。实际经营指标应以至少三个问题与权威报表对账。

后台员工不持有客户的业务 Token，不会自动借管理员身份调用客户分析接口。当前已提供独立服务凭据的指标桥、定期报告、签名外部工单同步、Tempo 和登记式 Playbook；都需要对应目标系统的具体适配及验收，见[进阶工作流](advanced-workflows.md)。

## 知识 Worker 的部署

`pnpm deploy:start` / `pnpm demo:start` 生成独立索引器容器配置并启动 `knowledge-worker`。该容器只拿索引数据库凭据及项目标识，不挂载 Core 的业务连接配置。源码部署流程会重建服务；需要维护窗口时按部署指南安排。

将允许扫描的材料放入 `.local/knowledge-sources/<product>`，后台填写容器路径 `/sources/<product>`。仅该根目录只读挂载，缓存使用独立 `.local/knowledge-cache`。不要填写宿主机任意目录并期待容器能读取。

Git 来源还需在 `.local/knowledge.env` 配置主机名单，例如：

```dotenv
AGENT18_KNOWLEDGE_GIT_HOSTS=["github.com"]
```

重启知识 Worker 后生效。URL 不得携带用户名、密码、Token、查询参数或自定义端口。私有仓库可在 Setup 保存绑定精确仓库的只读凭据引用，或先用部署者受控方式检出到允许目录；当前没有 GitHub App/OAuth 授权向导。模型配置读取 `.local/model.env`，未配置时原文扫描可用、模型生成明确失败，不返回虚构成功。

主机方式仍可使用 `AGENT18_KNOWLEDGE_ROOTS`、`AGENT18_KNOWLEDGE_GIT_HOSTS` 与 `pnpm knowledge:worker`。两种运行方式要使用各自真实可读的路径，不同时争用同一来源的维护流程。
