# 知识治理、业务分析与运行集成

本页对应本地工作树的完整后台实现，需运行至迁移 036 并构建新镜像。部署主机的 Setup 负责网络地址和凭据维护；日常员工在 `/admin` 工作。现有部署不会因修改代码自动升级。

## 知识接入与发布

1. 在知识中心连接目录或 HTTPS Git 仓库，设置 ref、包含/排除路径、文件和容量上限。目录必须在部署允许根目录内；远程 Git 主机也必须获准。
2. 私有 Git：本地接入工作台填写只读用户名/令牌、精确仓库 URL 和 `AGENT18_GIT_…` 引用。应用配置后，知识来源只填写引用。绑定保存在 `knowledge.env`；令牌不会进入数据库来源说明、Git URL、命令行参数或模型输入。Git 不跟随 HTTP 重定向。可保存、轮换或撤销引用；修改后重启知识 Worker 生效，即时吊销需同时在代码平台撤销令牌。
3. 扫描完成后，在知识地图选择最多五个固定版本识别范围候选。目录分组只是线索；名称可以修改，候选导入后仍需确认业务范围和逐条依据。不把仓库目录数称为“已理解业务数量”。
4. 可合并重复主题：源主题保留历史并标为已排除，目标重新进入范围确认；合并的证据重新核实，文档发布不变。
5. 选择经确认的固定片段生成分层内部文档；上传/人工资料通过来源或文档编辑补充。客户版本独立审核。
6. Playground 可对比当前发布和最多二十份固定修订的客户候选稿。黄金题支持预期答案、必须引用、禁止引用、不可回答题和优先级，记录候选正文/标题/类别指纹与实际引用。发布者可追加语义复核记录。高优先级题关联的客户稿必须有当前内容的候选回归通过；有预期答案还必须复核为正确，失败在单篇和批量发布事务内阻止发布。检索命中不自动等于语义正确。
7. 审核队列的发布集合一次发布最多三十份已审核文档。任何修订变化整批返回冲突；成功后保留每篇修订、Build 与先前发布引用。整批撤下也会检查当前发布，避免覆盖之后的新发布。恢复历史正文需重新审核。

## 业务分析与 Playbook

接入工作台的分析设置登记固定的 GET 路径、允许服务访问的租户、凭据引用、指标口径和可用维度。Core 使用单独的服务凭据读取聚合数据；员工仍需项目角色和租户授权，凭据不送往浏览器。客户自己的业务查询继续使用网站 Support Token，两条身份链分离。

每个指标需写明退款/取消、分母、单位、币种、时间归属、最大天数和口径版本。接口只能返回声明的数字及维度字段；额外字段、租户/项目/版本/时间范围不一致、超大正文或重定向都会失败。最多 1000 行、512 KiB；请求有超时。人工分析每账号每分钟最多 10 次，配额记录在数据库；HTTP 调用期间不持有员工权限锁，返回后重新验证授权。

请求形式：`GET <baseUrl><metric.path>?tenant=…&start=…&end=…&dimensions=store,day`。时间为完整 UTC 日的半开区间，分析时分别请求当前与等长上一周期。Header 包含 `Authorization: Bearer <service credential>`、`x-agent18-organization`、`x-agent18-project`；接入方必须独立验证服务授权和租户。

响应必须包含：`organizationId`、`projectId`、`tenantId`、`metricId`、`definitionVersion`、原样的 `start/end/dimensions`、`summary`、`rows`、`complete`、`generatedAt`、`sourceRevision`。`summary` 由权威接口计算，不能将分组比例/去重人数相加当总量。不完整数据会明确提示，不能据此解释总体下降。

参考适配器位于 `examples/analytics-bridge/reference.ts`。它通过独立 SQLite 和真实 HTTP 提供销售与网站转化两套不同口径，合成固定样本覆盖取消、退款、其他币种、重复访客及跨租户记录。它是协议参考，不能代替接入方对自己财务或网站统计的确认。

后台 Insights 的流程是“提问匹配指标 → 确认租户/周期/维度 → 查询 → 查看依据与限制 → 保存/导出”。未可靠匹配时显示目录供选择，不执行任意 SQL。保存的聚合报告仅创建者且仍拥有完整原始范围时可读取。

Playbook 是经过确认的分析参数模板：版本、目的、一个已登记指标、窗口和维度，固定 `TENANT / READ`。可在设置里从指标创建，参考实现提供经营复盘和网站转化复盘。加载模板仍需确认租户和参数；不会扩展工具或写权限。

客户支持中心可以从查询结果进入“办业务”，保留查询时间及记录作为参考，再选择获准操作、填写参数、查看真实业务预览并确认。后续执行沿用已有 ActionProposal、Policy 与业务回执。员工分析账号不能借用客户 Token 执行操作。

## 定期报告与任务恢复

选择当前客服统计或业务指标后，在 Insights 创建每日/每周计划，指定 IANA 时区及当地时间。每次执行创建个人不可变快照；任务页展示完成、失败和回执，并可打开报告。

- 同一计划/时间槽去重，多 Worker 通过数据库租约领取；进程中断后可回收过期租约。
- 暂停或归档取消未完成任务；手动运行/重新运行有次数上限，自动失败最多三次。
- 权限每次执行重新校验；员工停用/撤权会停止计划。分析配置指纹变化也停止旧计划，需审核后重建。
- 不保存客户短期 Token。报告由 Core 计算，队列 Worker 只持有内部工作负载身份。
- 夏令时缺失时刻跳过当日，重复时刻只执行一次；停机期间合并补跑，避免无限追赶。
- 删除报告后记录删除账本，恢复备份同时取消相应旧任务，避免重新生成被删除的快照。

## SLA 工作日历

管理员在工单页面设置各优先级目标分钟数，以及连续计时或工作日历。日历包含时区、每周工作日、同一天的起止时刻和休息日期。工单首次启用 SLA 时保存日历快照；后续配置变化不改写已有工单的累计口径。

等待客户、等待内部、解决、关闭暂停计时，重开继续累计。更改优先级使用当前启用的目标时间，保留工单日历及累计时间。首响和解决时限分别配置。首响采用同一日历，到首次公开回复或公开解决说明停止；内部备注和等待状态不停止首响。无历史时钟的旧单不追溯补算。

## 外部工单桥与通知

接入工作台配置 HTTPS 事件接收地址、允许租户及 `AGENT18_SYNC_…` 密钥引用。每张工单由有权限的员工显式开启同步，之后状态变化在同一事务写入 outbox。仅外发编号、版本、状态、优先级及删除标记，不外发客户原文、内部备注或日志。

投递 Headers 为 `x-agent18-event`、`x-agent18-timestamp` 和 `x-agent18-signature`。签名算法是 HMAC-SHA256，输入为 `timestamp + '.' + eventId + '.' + canonical(payload)`；使用项目提供的 canonical JSON 函数，不能对任意排版后的 JSON 签名。时钟容差五分钟。

外部接口必须按 eventId 保存幂等回执 `{eventId, externalId}`，并按工单版本处理更新。Core 最多重试五次，旧版本失败会阻止后续版本越过；最终失败可在工单页面重新运行。丢失回执后的重投必须返回原回执。

回传地址 `/integrations/tickets/events`，字段包括 `eventId`、项目/组织/租户、`ticketId`、`externalId`、递增 `version`、`status`（open/in_progress/waiting/resolved/closed）和 `origin`（external/agent18）。签名、连接范围和实时员工授权都要通过。重复事件回读原结果，低版本忽略，origin=agent18 的回环忽略。

外部状态单独显示；本平台解决工单仍需员工填写对客户可见的解决结果。连接配置变化后，先停止旧连接，再人工重新启用；原外部系统上的记录不会被默默删除。参考接收器 `examples/ticket-bridge/reference.ts` 使用 SQLite 持久化版本和幂等回执，也可在桥内对接企业已有通知平台。

## Trace 与部署证明

Tempo 检查通过 `GET /api/traces/<traceID>` 获取 OTLP JSON，按项目属性、租户属性和可选用户属性逐个校验 span。缺少 traceId、过期/未采样的轨迹显示未知；不能以无错误 span 证明服务健康。原始 Trace 证据仅工程可见，摘要继续脱敏。

生产应通过已有鉴权代理保护 Tempo，Core 只连接管理员固定的 URL；可设置租户到 `X-Scope-OrgID` 的固定映射。协议依据见 [Tempo API](https://grafana.com/docs/tempo/latest/api_docs/)；独立运行验证使用 [官方 3.0.0 单实例示例](https://github.com/grafana/tempo/tree/v3.0.0/example/docker-compose/single-binary)，执行 `pnpm exec tsx scripts/verify-tempo.ts` 会创建并清理隔离容器。

Operations 中可按服务、环境和事故时间查询部署记录。管理员人工登记需要完整 Commit、制品 sha256、实际部署时间、HTTPS 证明地址和核对说明，标记为“人工证明”。签名流水线通过 `/integrations/deployments/events` 提交同样的 `deployment` 对象及组织/项目/pipeline；配置中必须预先绑定允许的服务、环境和 sourceId，密钥引用为 `AGENT18_DEPLOY_…`。

流水线采用相同 HMAC 事件协议。记录不可覆盖；错误记录需要带理由撤销。查询使用事故时刻之前最近一条记录，撤销后显示未知，不回退猜测旧版本仍在线。知识新鲜度分别显示源文件变化和已记录部署版本的匹配情况；匹配不等于根因已证实。

## 接入验收与历史引用

集成页按开发、预发布和生产环境保存身份、知识、查询、办理、观测及指标对账的人工验收记录，要求实际样本说明与证据编号。服务加载配置的指纹变化后，已有结果标记过期。此表记录已执行的验收，不把配置存在或管理员填写记录称为自动健康检查。

持久对话保存最多五个知识/查询/提案/工单引用及观察时间，不缓存整份业务结果。引用属于当时的客户展示数据，不能授权当前操作。恢复时不自动读取或重放业务写入，只把最近六条用户文本（每条最多 256 字符）作为受限对话线索。对话删除和恢复删除重放会同时清除引用。

知识冲突页可扫描同主题内明确的数值赋值，按同名规则、同一单位识别不同值；不执行代码表达式，也不换算未知单位。扫描最多 100 项固定依据、每项 20,000 字符，只生成候选；人员还须核对共同版本和业务范围后登记，由发布者裁决。

本地慢速模型可通过 `AGENT18_MODEL_TIMEOUT_MS` 设定最多 180,000 ms；默认仍为 30,000 ms，单次主题任务仍有五分钟总预算。建议先对实际代码样本评测，不能因 JSON 格式有效就自动发布生成结果。

观测工具升级：迁移 036 将原装 `operations.observe` 更新为 v2（provider 1.1.0），保留已撤销状态。曾通过 Registry 自行导入或审核过的绑定不会被迁移覆盖；部署者须通过现有 `pnpm registry import` / `inspect` / `approve` 流程重新核对完整描述与 fingerprint，不能仅修改版本绕过描述校验。
