# 用一个对话入口持续完成事情

浮窗和内嵌助手使用同一个消息流与输入框。用户不用先判断问题属于知识、业务查询还是客户支持；助手根据当前这句话和最近的用户消息，给出下一步引导。独立支持页继续提供完整目录与工作区，适合查看较多内容。

## 可以直接体验的对话

在示例 SaaS 右下角打开助手：

1. 输入“查询我的订单”，在消息中看到当前用户的真实订单。
2. 输入“查看订单详情”，助手追问订单号；再输入“ORD-1001”。
3. 输入“关闭邮件通知”，看到变更预览。只有点击这张卡片的“确认执行”才会提交；在输入框里单独说“确认”不会执行。
4. 输入“如何接入现有网站？”，再问“那需要什么权限？”，检索和回答会参考最近的用户问题。
5. 输入“问题还是没解决，联系支持”，核对对话中整理的问题说明，再明确提交。之后说“我的问题进展”可以继续查看和回复。

没有模型 Key 时也有确定性的意图匹配、能力选项与参数追问；复杂自然语言理解和指代改写由配置的模型辅助。无法确定时会提供选择，不承诺任意表达都能自动理解。查询结果、参数选项、知识引用与操作确认都在消息中展示。

## 请求怎样流转

SDK 的 `routeConversation({ message, history, pending })` 请求 `/api/assistant/route`。Core 校验客户身份和策略，仅向规划器提供当前角色可用的查询与操作定义；最近最多六条用户消息用于上下文，待补参数携带类型、操作 ID 与已明确填写的值。

路由只返回知识问题、查询/操作候选、帮助、问题跟进或取消。它不访问业务 API、不创建提案、不确认操作。SDK 收到候选后继续调用现有知识、查询、prepare 和 Case API；缺少必填信息时继续追问。模型返回的未知 ID、未知字段、错误类型会被拒绝并回退到确定性引导。

代操作仍走 prepare → 用户点击具体预览的确认按钮 → execute → 回执。文字“确认”不能替代具体预览的确认，也不会自动把上一项操作再次执行。结果不确定时卡片只允许核对同一业务回执。

## 对话生命周期

关闭再打开同一个浮窗会保留当前页内的消息和输入。刷新页面或销毁 SDK 挂载后开始新对话；普通聊天内容没有新增数据库历史，也不存入浏览器持久存储。客户主动提交的问题、跟进消息和业务提案仍由现有后端持久化。

路由的模型上下文不包含 SDK 自动抓取的页面 DOM、Token、原始业务返回或完整客服历史；只使用显式的用户消息、待补参数、可用能力定义和当前实体提示。接入者切换登录用户时应销毁旧助手并重新挂载，避免在同一界面保留上一位用户的对话展示。

## 验证

单元测试覆盖无模型引导、追问、知识上下文、取消、未知模型工具/字段与故障回退；HTTP 集成测试覆盖当前身份可用目录、没有权限的操作不能被规划、规划阶段不写业务提案。业务执行继续接受既有权限、幂等和回执回归测试。
