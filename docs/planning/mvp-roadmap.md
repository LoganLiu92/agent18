## A. 让一个陌生项目顺利接入

| 交付 | 前置依赖 | 出口验收 |
| --- | --- | --- |
| 可重复的发行产物 | Server/Worker 编译产物、生产依赖、迁移与运维脚本打包、许可证审查 | 无本机 Node/pnpm 的干净主机通过已发布镜像完成初始化、运行、升级、备份和恢复；版本/digest 与源码对应，提供 SBOM 与来源证明 |
| SDK 分发与参考集成 | 明确发布范围、类型导出、许可证和兼容性策略 | 一个现有框架前端和一个独立后端完成真实会话签发、租户切换、引用回答、查询、确认写入和回读；SDK 安装与销毁可复现 |
| 宿主语义上下文 | 版本化 context/event schema、SDK 有界缓存、隐私预览 | 路由变化与失败业务事件能够定位“当前订单为什么提交失败”；旧线索过期，切换用户清空，伪造事件不能扩大查询权限 |
| 受控的更多查询协议 | 固定地址、只读契约、输入输出投影、可信身份与角色映射 | 一个 POST 查询适配器通过成功、越权、超时、超大响应和配置撤销测试；GET 自动导入保持保守，声明 READ 本身不证明上游无副作用 |

本阶段优先解决实际目标系统的接入障碍。React 包、CLI 和更多后端示例按复用需求加入，保留无框架 Web SDK；具体 npm scope 与镜像位置须在发布并验证后进入安装说明。

## B. 让客服团队能够持续处理问题

| 交付 | 前置依赖 | 出口验收 |
| --- | --- | --- |
| 持久 Conversation | 会话/消息 RLS、分页、幂等、保留与删除语义 | 刷新后继续自己的对话，关联查询/操作/Case；跨用户与跨租户读取被拒；身份切换清理浏览器缓存；删除后的恢复和索引访问遵守删除策略 |
| 远程客服工作台 | 独立 Operator 身份、OIDC、项目授权、审计与撤权 | support/engineer/admin/viewer 的队列、分配、回复、内部备注、工程证据权限分别验收；客户角色不能进入；不用对公网代理当前本地 Owner 服务 |
| 可靠的外部事件 | 与业务事务一致的 outbox、签名、投递租约、重试、去重和人工重放 | case/action/investigation 事件接入一个真实外部系统；重复、乱序、接收端故障与回写循环可控；投递默认不含 Token、截图和完整日志 |
| 知识改进循环 | 会话失败信号、受众过滤、人工解决记录、离线评测集 | 聚类相同知识缺口，生成带来源的草稿；用保留样本比较当前版和候选版的引用、拒答、意图/参数、延迟与成本，审核后发布 |

外部客服或工单系统可继续承载坐席管理和通知。Agent18 的事件是至少一次投递合同，接收方按 eventId 去重；不能承诺跨系统“恰好一次”。

## C. 把排查结论连接到运行证据

| 交付 | 前置依赖 | 出口验收 |
| --- | --- | --- |
| Trace 后端适配 | 明确选择一个后端、租户过滤与只读凭据，定义 Provider 合同 | 已知失败请求能找到对应 span、错误和关联日志；无权限/采样缺失/过期 Trace 返回未知，随机 traceId 不能越权 |
| 证据关联视图 | Case/session/entity/request/trace 的来源和时间标识 | 每条关联可解释由谁提供、是否已验证；工程师能从页面故障追到请求、服务和日志，不以时间相近直接认定因果 |
| 发布版本关联 | 宿主或 CI 提供可信 release/commit/image digest 与发布时间 | 关联事故发生时的部署，保留缺失或冲突；不能用当前 HEAD 代替事故版本 |
| 能力目录和适配规范 | 统一元数据与审核视图，保留业务读、确认写、工程观测的独立执行入口 | 能列出能力版本、效应、角色、范围、审核状态和来源；撤销/定义变化继续失效，新增 Transport 不能绕过 Gateway 和业务确认 |
| 知识 Provider 扩展 | 来源授权、快照、受众、引用和撤权合同 | 新解析器/检索后端保持 scope 预过滤和历史引用撤权；大型仓库有覆盖率、预算和增量构建报告 |

先交付一个真实 Trace 适配器，再按目标项目扩展。OTel 负责遥测生成、采集与导出，存储查询仍需具体后端，参见 [OpenTelemetry 官方说明](https://opentelemetry.io/docs/what-is-opentelemetry/)。Agent18 将 MCP 作为连接协议适配，保留自己的授权控制；[MCP 架构规范](https://modelcontextprotocol.io/specification/2025-11-25/architecture)也将连接权限、授权和安全策略列为 Host 的职责。代码修复在可信证据与人工交接成熟后推进。

## 生产接入门槛

以下项目均为**待实现的增强**。A/B/C 的新能力不得以跳过这些依赖为代价宣称适用于相应生产场景。

| 项目 | 当前约束 | 交付验收 |
| --- | --- | --- |
| 分层持久配额 | 单进程并发和用户窗口 | 两个 Core 实例共享 project/tenant/subject 预算与租约；重启不重置额度；租户间公平；429 有 Retry-After，超时释放与幂等重试不重复收费 |
| Agent18 自身遥测 | 健康检查、持久审计和少量错误日志；HTTP logger 关闭 | 请求/依赖/模型/队列/排查指标关联 requestId；不默认采集正文、JWT、截图或高基数用户标签；慢依赖和 uncertain 操作可见 |
| 身份与租户生命周期 | 静态 Ed25519 公钥、手工登记租户、本地 Owner | 可信 issuer/JWKS 轮换与撤权可验证；租户配置由管理身份或可信解析器处理；新 Token claim 不能自行开通租户 |
| 高风险业务 | 写操作必须明确确认；无高风险二次认证/双人审批 | 批准绑定内容、当前权限、版本与期限；二次认证和双人审批不能由模型或客户自行伪造；低风险分级不取消现有确认默认值 |
| 密钥、数据保留与审计 | 本地配置/备份，未提供全套轮换、TTL 和审计导出 | 凭据轮换失败时关闭能力；按类别和租户删除截图/会话/日志摘要，保留必要审计；备份和恢复遵守删除策略；导出访问可审计 |
| 多实例与灾备 | 当前交付承诺单机运行与隔离恢复演练 | 多实例公平调度、租约崩溃恢复、迁移互斥和配置一致性；在实际负载下验证 RPO/RTO 与离机恢复 |

## 后续有条件交付

多步业务办理以审核过的 Workflow 为单位，明确参数、条件、确认点、超时、补偿与最终回读。先做一个真实且可恢复的流程，再推广注册合同；模型不能自行拼接任意写操作。

代码修复依次交付工程证据交接、修复建议、隔离测试、草稿 Issue/PR。每个外部写入保留授权和回执；自动合并、生产部署与通用 Shell/SSH 不属于当前交付。

关于每条外部评审建议的核实结果、优先级和暂缓原因，见[评审核验与研发优先级](review-and-priorities.md)。
