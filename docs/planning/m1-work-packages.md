**F01 / F02：基础合同**

交付：共享 entityKey/sameEntity、前后端 namespace 保存/展示、来源快照与生成记录；定义 Source Revision 与 Deployment Revision。验收同编号跨业务域、旧数据缺 namespace、快照冻结、客户 DTO 不暴露内部生成元数据。完整知识模型迁移在 K01，不把当前 build.report JSON 称为已完成 Topic 模型。

**A01：独立账号**

交付：部署向导创建第一位管理员，`/admin` 登录，项目与角色查看，工作人员创建/停用/授权，首次改密与管理员重置，退出与会话撤销。客户 Support Token 不被后台接受，后台 Cookie 不可用于客户业务接口。

验收：无默认口令、无公开注册；同源写入与 CSRF；账号/地址限流；密码哈希与凭据脱敏；停用/改密/改权限立即失效；不能删除最后一位可用管理员。具体请求目前位于 `/operator/*`，不混入客户 `/api/*`。

**A02：独立账号运行闭环**

- 交付：部署者可在本地维护入口恢复指定管理员，审计说明是部署者恢复；补操作审计页面、账号列表分页/筛选、账号配置与备份恢复说明。
- 将项目角色校验抽为同一服务：知识查看、编辑、审核/发布、内部证据读取分别校验；每个实际 API 都接入，而不是只在前端隐藏按钮。
- 验收：忘记管理员密码可按维护步骤恢复；远程访问无法触发 Owner 恢复；会话撤销与并发授权变更复核；跨项目/无权限拒绝；恢复备份后会话的失效规则明确。
- 主要位置：`apps/server/src/operators`、Setup 本地维护入口、Console 管理页及账号集成测试。

**K01：知识模型与迁移**

- 后端：新增 SourceSnapshot/SourceEvidence、Topic/TopicEvidence、Document/Revision、ReviewDecision、Publication 及必要关联；所有引用强制 project scope；索引器与 Operator 权限分离。
- 数据迁移：建立旧 build/article 到新模型的映射，保留原引用；历史信息不足标记 legacy/unknown。同步定义新旧检索优先级。
- 初始页面：知识中心空状态、主题目录及只读详情，能看到真实入库数据和缺失状态。
- 验收：一个主题关联代码和业务说明两类证据，生成两个受众的独立文档；跨项目关联拒绝；旧发布和旧 Case 仍能读取；迁移失败不改变活动发布。
- 主要位置：`packages/knowledge`、持久层新增迁移、Server Operator 路由、客户 KnowledgeProvider。

**K02：来源连接与可恢复扫描**

- 页面：选择 Git/目录/文本资料，连接测试，ref、范围、受众配置；扫描预览显示已读/跳过、容量与失败原因，支持取消/重试/刷新查看。
- 服务边界：远程账号不能随意读取部署主机路径。目录来源由部署者配置允许根目录；Git 只读凭据以服务端引用管理，URL 不携带凭据；拒绝越界路径、符号链接与未批准网络目标。
- 扫描任务持久化状态、输入版本、租约和尝试记录；复用现有任务机制，单独声明 knowledge 任务类别，不复用客户工单业务语义。
- 预算：记录来源文件/字节/模型调用上限；取消后停止继续调度。重试使用原始快照或明确创建新快照，不静默换到 HEAD。
- 验收：中断/重启可恢复或明确失败；无权限、凭据错误、超限、文件变更均有可操作提示；成功预览尚未向客户发布任何内容。

**K03：产品理解与知识地图**

- 页面：候选业务域、模块/来源映射，用户选择产品范围；可重命名、合并、增删主题及调整必要文档类型。
- 分析：先支持试点技术栈；规则/解析器识别与模型推断分别记录。模块/API/状态机数量必须可以打开对应证据，无法识别不能显示零并暗示不存在。
- 首页：按业务域展示已确认主题、证据、已发布文档、待审核与缺口；覆盖率有分子、分母及口径。初次进入引导完成尚缺步骤。
- 验收：用户可排除不属于产品的工具/测试模块；同义主题合并不丢证据；一次刷新不丢已确认地图；模型不可用时可手工维护目录，不伪装自动业务理解。

**K04：生成与补充**

- 页面：按主题勾选产品/用户/API/工程/运维文档类型，选择内部或客户候选，查看预算并开始；生成过程可见，结果关联来源。
- 生成按固定 Topic + 获准 Evidence + 目标受众/层次执行。现有逐文件文章生成可以复用解析/模型适配器，但不能冒充跨来源分层产品文档。
- 手工补充业务规则、导入文本说明并绑定 Topic；缺口可以补资料、手工写稿或记录暂不适用。完整文件上传解析、网站抓取和第三方文档平台另立任务。
- 验收：从代码证据与业务说明生成互补内容；证据不足明确待核实；模型超时/格式错误保留失败记录；二次生成不覆盖人工修订；成本和缓存复用可核对。

**K05：编辑、审核与发布**

- 页面：正文编辑与证据侧栏、修订差异、提交审核、退回理由、发布前清单、发布记录、撤下与回滚。
- 编辑请求带 baseRevision/expectedVersion；冲突返回 409，不覆盖他人内容。审核绑定具体 revision；发布者权限与来源可见性在事务内复核。
- 客户衍生版通过独立脱敏审核，公开引用指向正式文档。禁用来源/收紧权限即时影响后续回答，历史引用重新授权。
- 验收：编辑者无发布权限时不能发布；新稿不能继承旧审核；并发发布、重复请求、回滚和权限撤销均有确定结果；当前已发布版本不受失败生成影响。

**K06：阅读、问答与评测**

- 页面：内部知识浏览和客户可见预览；提问、答案与证据；评测集编辑、候选/发布版对比、失败样本定位。
- 首轮 20 题构成固定为概念 5、规则 5、操作 5、API/错误 3、不可回答 2；另设跨租户/内部来源/撤销资料访问测试，不能仅靠 20 道内容题覆盖权限。
- 每题保存 expectedAnswer/allowedEvidence/forbiddenEvidence/audience/tenant/version；用明确断言校验引用和隔离，语义正确性需人工标注或复核。自动评测使用候选隔离读取路径，不能提前发布。
- 验收：重建可自动回归并保留比较结果；高优先级事实错误、禁用来源泄露或不可回答幻觉阻止相应发布；模型/检索器替换前后有同一组证据。

**K07：真实接入验收**

首轮目标未指定时，Agent18 自身代码/文档仅作为开发样本，不称为真实客户验收。选定成熟项目后固定源码 commit、部署版本（如有）、产品域和客户资料，实走连接 → 地图 → 分层生成 → 补充 → 审核 → 发布 → 真实问题 → 证据回溯。

验收报告分别记录正确、失败、未知、未接入；由实际业务人员确认规则和用户指南。任何本地测试账号、模拟模型或合成知识都必须标明。真实模型调用的费用与出站资料范围按配置控制。
